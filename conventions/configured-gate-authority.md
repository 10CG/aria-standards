# Configured Gate Authority 规范 — 已配置闸门的权限归属

> **Version**: 1.0.0
> **Status**: Active
> **Source incident**: 2026-07-19 (Aria #166 cycle) — AI 以「Level 2 + 任务是已 audited SC 的 1:1 派生 / 性价比不高」为由, 自行跳过 config 里 enabled 的 `post_planning` 审计检查点
> **Owner 裁决**: 2026-07-19 — 不认可自行豁免; 并**否决**「先跟踪 AI 判断准确率再自动放权」方案 (理由见 §4)
> **对应规则**: Aria CLAUDE.md 不可协商规则 **#10**

---

## 1. 规则

> **配置里 enabled 的闸门, 是配置者 (owner) 的决定, 不是 AI 的临场判断题。**

AI **不得**以下列理由自行跳过、降级或改序一个已启用的闸门:

- 「本次变更小 / Level 低」
- 「被审对象是已经审过内容的 1:1 派生, 再审是重复劳动」
- 「性价比不高 / 这次大概率查不出东西」
- 「session 已经很长 / 时间紧」
- 「后面还有别的闸门会兜住」

这些**全部**是对**闸门是否值得跑**的评估 —— 而闸门的价值恰恰在于:
**你事先不知道它这次会不会抓到东西**。事先知道会抓到, 就不需要闸门了。

**适用面**: 审计检查点 (audit checkpoints)、CI/pre-merge gate、必跑的 review、
强制的测试套件 —— 任何「配置声明为开、由 AI 在流程中触发」的关卡。

## 2. 豁免的合法来源 (fail-closed 白名单)

豁免**只能**来自**已写明的机制**, 不能来自 AI 临场判断。合法来源穷举:

| 来源 | 例 |
|------|-----|
| 配置显式关闭 | `.aria/config.json` `audit.checkpoints.X = "off"` |
| 配置的自适应映射 | `audit.adaptive_rules` 的 Level → mode 映射 |
| 已成文的 lane 降级 | emergency hotfix lane 把 `pre_merge` 降为 convergence |
| 闸门自身的结构性前提不成立 | 某 checkpoint 审的是 A.2 产物, 而 A.2 整个未执行 → 无对象可审 |

> **注意最后一条的边界**: 「A.2 没做, 所以没东西审」是合法的; 「A.2 做了但做得很简单, 所以不值得审」**不是** —— 前者是对象不存在, 后者是价值评估。**这条边界最容易被滑过去**, 2026-07-19 事故就滑在这里 (产出了一份薄 tasks.md, 却按「几乎等于没做 A.2」自我豁免)。

不在上表内的跳过 = **违规**。

## 3. 为什么 (两条独立理由)

### 3.1 闸门的收益不可事前预知 (source incident 实证)

2026-07-19 Aria #166 cycle: AI 跳过了 `post_planning`, 但**跑了的** `post_spec`
在同一 cycle 抓到 **1 Critical + 1 Major** —— 其中 Critical 是「修复位置钉错文件」
(继承了 issue 报告者自身的 mis-citation)。若该轮也被以同样理由跳过, 结果会是:
**全部测试通过、全部验收标准满足, 而 issue 描述的真实危害原封不动**。

同一套「这次大概率查不出东西」的推理, 这次省了一轮, 下次就会漏掉一个 Critical。

### 3.2 判断者与被判断者是同一方 (结构性利益冲突)

决定「要不要审我自己」的是**被审方**, 而「省掉一轮审议」对执行者有直接收益
(时间、上下文预算、任务尽快收尾)。这使该判断**天然不中立** —— 哪怕某次结论碰巧正确,
把这个判断权放在这一侧本身就是错的位置。

## 4. 为什么不采用「跟踪 AI 判断准确率 → 逐步放权」

一个直觉方案是: 记录 AI 每次「跳过」判断, 统计准确率, 准确率够高就让它自主决定。
**该方案经评估否决**, 理由如下 (2026-07-19 owner 决策):

### 4.1 跳过即销毁标签 (结构性, 非记录粒度问题)

要评估「跳过是否正确」, 需要知道**不跳会发生什么** —— 但那轮闸门从未运行,
它会不会抓到东西**永远没有答案**。这不是记录得不够细, 是这类判断的固有形态:
**动作本身消灭了它的评估依据**。

### 4.2 唯一诚实的设计代价高于收益

能拿到真标签的设计只有一种: **照跑 + 把 AI 的判断封存起来做对照** ——
AI 说「可跳、理由 R」→ 记下 → **闸门照跑** → 看它实际有无实质发现 → 得一条真标签。

但:
- 校准期**一分钟都不省** (照跑就是全价), 买的只是「将来可能能省」的资格;
- 需要足够样本量才有统计意义, 按小团队的决策频次要攒**数月以上**;
- 判断类别之间**不可互换** (「该不该跳审计」的准确率, 说明不了「该不该判这个 flaky 无关」的准确率), 分类后样本更稀疏;
- 而它要省下的, 是一轮小规模审议的时间。

**量具比被测物更贵。**

### 4.3 便宜的替代版本比没有更糟

退而求其次的「跳过后没出事 = 判断正确」有一个致命偏差:
**它只能数出错的次数, 永远数不出对的次数**。没出事不等于跳对了 ——
也可能是问题还没浮出来。

于是它会稳定产出一串漂亮数字, 而**对「跳错了但还没爆」这唯一重要的情况完全失明**。
比没有更糟的地方在于: **它会拿假证据给 AI 发更大的自由裁量权**。

> 这与「一个在该失败时不会失败的检查, 不是检查」是同一个病根 —— 只是这次
> 假绿长在**元层面** (评估机制自身)。

### 4.4 照跑本身就是数据采集

**不需要另建机制**: 每次照跑都产生一条真实观测「这类场景下它抓到了什么」。
累积若干轮后:

- 若它在该类场景反复零收获 → 你获得**实证依据**去写豁免规则 (数据挣来的, 非 AI 声称的);
- 若它某次真抓到了 → 问题自动结案。

两条路都通向答案, 且零额外维护。区别只是: **先付钱后拿证据, 而不是先拿自由后补证据。**

## 5. 配套习惯 (低成本, 必做)

AI **任何**自作主张的流程判断 (跳过 / 降级 / 改序 / 替代), 无论是否落在 §2 白名单内,
都必须在 **session handoff 中显式写出**:

```
跳了什么 + 理由 + 请 owner 复议
```

它测不出准确率, 但它保证这类判断**永远不会悄悄沉淀为惯例**。
2026-07-19 事故正是靠这条才被摆上台面并得到裁决。

## 6. Enforcement layer (诚实声明)

| Layer | 状态 |
|-------|------|
| **Layer 0** — Prose convention (本文档) + 项目 CLAUDE.md/AGENTS.md 规则条目 | ✅ 本规范 |
| **Layer 1** — 编排层机械校验 (phase skill 在触发闸门前断言 config 状态一致) | ❌ **未实施** |
| **Layer 2** — Hook / 运行时阻断 | ❌ **未实施** |

> **当前仅 Layer 0** —— 依赖 AI 读到并遵守, 无机械兜底。
> 这是**已知局限**, 不要因为本文档存在就认为该约束是被强制执行的
> (那正是本规范 §4.3 批判的那种假绿)。若未来某闸门反复被绕过, 应升级到 Layer 1。

## 7. 采用方适配 (第三方项目)

本规范不绑定 Aria 的审计系统。采用方按下列方式落地:

1. **列出你的闸门**: 项目里哪些关卡是「配置声明为开、由 AI 在流程中触发」的
   (CI gate / 强制 review / 必跑测试 / 审计检查点)。
2. **在 AI 指令文件中写死本条**: 把 §1 规则 + §2 白名单写进 `CLAUDE.md` /
   `AGENTS.md` 的不可协商规则区 (AI 每 session 会读到的地方)。
3. **§2 白名单按你的配置具体化**: 把「合法豁免来源」写成你项目里真实存在的配置项,
   而不是抽象描述 —— 白名单必须**可穷举、可核对**, 否则 fail-closed 失效。
4. **保留 §5 习惯**: 无论有无审计系统, 「AI 自作主张必须在交接里显式记录」都成立,
   且成本几乎为零。
